# 未来规划

## 一、定位

系统按三阶段演进，每阶段有明确目标。

---

## 二、演进路线

### 第一阶段：本地 RAG（当前）

**目标**：打牢文档处理和检索基础。

| 组件 | 状态 |
|------|------|
| Docling 文档解析 | 已部署 |
| PostgreSQL 业务数据库 | 已部署 |
| Qdrant 向量数据库 | 已部署 |
| Embedding 服务 | 已部署 |
| Reranker 服务 | 已部署 |
| MinIO 对象存储 | 已部署 |
| Obsidian Vault 基础配置 | 已部署（Windows 侧 + MCP） |
| 文档处理流水线 | 待实现 |
| RAG 检索流程 | 待实现 |

**LangGraph**：暂不引入。

### 第二阶段：单 Agent

**目标**：完成一个稳定工作的 Research Agent。

| 组件 | 状态 |
|------|------|
| FastAPI + LangGraph | 待实现 |
| Research Agent | 待实现 |
| OpenAI Compatible API | 待实现 |
| Checkpoint（PostgreSQL） | 待实现 |
| 完整 Workflow（Planner → Retrieve → Reason → Reflect → Finish） | 待实现 |
| Research Agent → Obsidian Vault 自动写入 | 待实现 |

**LangGraph**：开始引入，作为 Workflow Engine。

### 第三阶段：多 Agent

**目标**：LangGraph 成为系统核心，支持多种 Agent。

| Agent | 用途 |
|-------|------|
| Chat Agent | 简单问答 + RAG |
| Research Agent | 研究分析（年报、行业） |
| Investment Agent | 投研分析（DCF、竞争分析） |
| Learning Agent | 学习辅导 |
| Maintenance Agent | 后台任务（扫描 PDF、自动处理） |
| Knowledge Agent | Vault 知识管理（双向读写 + 索引维护） |

---

## 三、技术扩展

| 扩展 | 说明 | 优先级 |
|------|------|--------|
| Redis | 高性能工作记忆、任务队列 | 中 |
| Celery | 异步任务调度 | 中 |
| MCP 扩展 | GitHub、Filesystem 等 MCP Server | 低 |
| 定时 Agent | APScheduler / Cron 定时执行 | 低 |
| 多模型路由 | 根据任务复杂度选择不同模型 | 低 |
| Web Search | 网络搜索 Tool | 中 |
| TuShare / AKShare | 金融数据源接入 | 中 |
| Vault 驱动的多 Agent 协作 | Agent 通过 Obsidian Vault 异步协作 | 高 |
