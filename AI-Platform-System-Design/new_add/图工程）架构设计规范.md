# 一、什么是 Graph Engineering？

Graph Engineering（图工程）并不是传统意义上的**图数据库（Graph Database）**，也不仅仅是 **LangGraph** 或 **知识图谱（Knowledge Graph）**。

Graph Engineering 是一种 **AI 系统架构设计理念**：

> **将 AI 系统中的代码、工作流、记忆、反馈等所有能力统一组织成一个动态演化（Dynamic Graph）的图结构，由 Graph Engine 统一调度与管理。**

传统的软件系统通常采用固定流程（Static Pipeline）：

```
A
 ↓
B
 ↓
C
 ↓
结束
```

而 Graph Engineering 则采用动态图：

```
Planner
     │
     ▼
Task Graph
     │
     ▼
根据当前状态动态生成
新的节点
新的流程
新的工具
```

整个系统可以根据环境、数据、反馈不断演化。

# 三、四种核心 Graph

---

# 1、Code Graph（代码图）

## 定义

Code Graph 用于描述整个项目的代码结构及依赖关系。

它不是简单的 AST（抽象语法树），而是整个项目的依赖图。

例如：

```
AI Platform

src/
    agents/
    workflows/
    rag/
    parser/
    providers/
    llm/
```

Graph 会自动建立：

```
Parser
    │
    ├──── Chunker
    │
    ├──── Embedding
    │
    └──── Vector Store
```

或者：

```
AnnualReportPipeline

↓

DownloadPDF()

↓

Docling()

↓

Markdown()

↓

Chunk()

↓

Embedding()

↓

Qdrant()
```

---

## Code Graph 包含内容

- Module
- Package
- Class
- Function
- API
- Tool
- Agent
- Docker Service
- 数据流(Data Flow)
- Import Dependency

例如：

```
ResearchAgent
        │
        ├── Downloader
        ├── Parser
        ├── Retriever
        ├── Writer
        └── Reviewer
```

---

## Code Graph 的作用

AI 可以：

- 理解整个代码结构
- 自动寻找工具
- 自动寻找 API
- 自动生成调用关系
- 自动修改代码
- 自动生成 Workflow

|--------|----------|------|

# 十一、总结

Graph Engineering 并不是一个具体的软件框架，而是一种面向 AI 系统的架构思想。

它通过将 **代码（Code）**、**任务（Workflow）**、**记忆（Memory）**、**反馈（Feedback）** 和 **知识（Knowledge）** 等能力组织为统一的动态图，使 AI 平台具备以下特性：

- **动态执行（Dynamic Execution）**：根据上下文实时生成和调整工作流。
- **统一调度（Unified Orchestration）**：Graph Engine 协调 Agent、Tool、Memory 与 Workflow。
- **持续学习（Continuous Learning）**：通过 Feedback Graph 积累经验，不断优化执行策略。
- **知识沉淀（Knowledge Accumulation）**：融合结构化关系与向量检索，形成长期记忆。
- **可扩展性（Scalability）**：支持新增 Agent、Tool、Graph 类型，而无需重构整体架构。

对于 AI Platform、多 Agent 系统和企业级 AI 应用而言，Graph Engineering 提供了一种统一、高扩展、可持续演化的架构范式，可作为未来平台设计和能力演进的核心基础。
