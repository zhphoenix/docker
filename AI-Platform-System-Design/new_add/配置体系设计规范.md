# AI Platform 配置体系设计规范（Configuration Architecture）

> Version: v1.0
> Author: AI Platform
> Last Updated: 2026-07-27

---

# 1. 设计目标

AI Platform 将长期运行，并不断增加：

- 新模型（LLM、Embedding、Reranker、OCR）
- 新数据源（AKShare、SEC、CNInfo、Firecrawl……）
- 新 Agent
- 新 Pipeline
- 新 Collection
- 新存储

因此，所有配置不能全部写进代码，也不能全部放进 `.env`。

本规范定义整个 AI Platform 的配置体系。

---

整个系统采用四层配置。

# 3. 第一层：.env（环境配置）

## 作用

用于保存**部署环境相关**配置。

这些配置在不同机器、Docker、WSL、Windows、NAS、云服务器之间可能不同。

例如：

```env
########################
# Database
########################

POSTGRES_HOST=postgres
POSTGRES_PORT=5432

########################
# MinIO
########################

MINIO_ENDPOINT=minio:9000
MINIO_ACCESS_KEY=minio
MINIO_SECRET_KEY=xxxxxxxx

########################
# Qdrant
########################

QDRANT_HOST=qdrant
QDRANT_PORT=6333

########################
# API
########################

DOC_PARSER_API=http://docling:8003
EMBEDDING_API=http://embedding:8001
RERANK_API=http://reranker:8002

########################
# Model Path
########################

MODEL_ROOT=/models

CHAT_MODEL_PATH=/models/Qwen3-32B
EMBEDDING_MODEL_PATH=/models/Qwen3-Embedding-4B
RERANK_MODEL_PATH=/models/Qwen3-Reranker-0.6B
OCR_MODEL_PATH=/models/Unlimited-OCR

########################
# Directory
########################

DATA_ROOT=/data
CACHE_DIR=/data/cache
TEMP_DIR=/data/tmp
REPORT_DIR=/data/reports

########################
# Feature
########################

ENABLE_RERANK=true
ENABLE_WEB_SEARCH=true
ENABLE_MULTI_AGENT=true

########################
# Logging
########################

LOG_LEVEL=INFO
```

---

## .env 只保存：

✅ 地址

✅ 端口

✅ 密钥

✅ 本地路径

✅ API

✅ 环境变量

不要保存：

- Collection 信息
- Agent 信息
- Chunk 参数
- Prompt
- Pipeline

# 4. 第二层：config/*.yaml（平台配置）

## 作用

保存平台资源定义。

这些属于：

**平台架构**

而不是：

**部署环境**

例如：

```

    collections/

    agents/

    models/

    providers/

    pipelines/

    prompts/
```

# 10. 第三层：Registry（注册中心）

## Registry 是什么？

Registry 不是一种新技术。

它是一种软件架构模式。

作用就是：

> 统一管理所有资源。

系统启动时：

```
config/

    collections/

        *.yaml
```

全部扫描。

自动注册。

形成：

```
Collection Registry
```

同理：

```
Model Registry

Provider Registry

Agent Registry

Pipeline Registry
```

全部自动生成。

---

## Registry 工作流程

```
config/

    collections/

        annual_report.yaml
               │
               ▼

      Registry Loader
               │
               ▼

     Collection Registry
               │
               ▼

registry.get_collection("annual_report")
```

代码永远不要写：

```python
collection="annual_report_chunks"
```

统一：

```python
registry.get_collection("annual_report")
```

---

# 11. Registry 的优势

## 不需要硬编码

错误：

```python
collection="research_chunks"
```

正确：

```python
registry.get_collection("research")
```

---

## 新增 Collection 不修改代码

新增：

```
research_cn.yaml

research_us.yaml

research_hk.yaml
```

Registry 自动加载。

---

## 可以保存大量元数据

例如：

```yaml
embedding: qwen3

reranker: qwen3-reranker

vector_size: 2560

distance: Cosine

chunk:

    size: 1200

    overlap: 200

payload:

    company

    year

version: v2

enabled: true
```

这些都不是 env 应该保存的内容。

# 14. Bucket 是否参数化？

Bucket：

```
documents

knowledge

datasets

artifacts

staging
```

建议：

**固定命名。**

Bucket 更像数据库 Schema。

不要放进 `.env`。

原因：

Bucket 一旦修改：

```
documents
```

↓

```
docs
```

程序就会访问空 Bucket。

容易造成系统异常。

---

真正应该参数化的是：

```env
MINIO_ENDPOINT

MINIO_ACCESS_KEY

MINIO_SECRET_KEY

MINIO_USE_SSL
```

---

# 15. Collection 是否参数化？

Collection 名称建议：

**不要放 .env。**

采用：

Collection Manifest

Registry

统一管理。

例如：

```
collections/

    annual_report.yaml

    research.yaml
```

代码：

```python
registry.get_collection("annual_report")
```

而不是：

```python
os.getenv("QDRANT_COLLECTION_REPORT")
```

# 17. 最终推荐的配置架构

| 层级 | 保存内容 | 是否经常变化 |
|------|----------|-------------|
| `.env` | 环境配置（地址、端口、密钥、路径、API） | 是（随部署环境变化） |
| `config/*.yaml` | 平台资源定义（Collection、Model、Agent、Provider、Pipeline） | 偶尔（随架构升级） |
| Registry | 启动时加载后的统一资源注册中心 | 自动生成 |
| PostgreSQL | 用户配置、运行时策略、任务、权限等动态数据 | 经常（运行时） |

---

# 18. 核心设计原则

1. **环境与业务分离**：部署相关配置放 `.env`，业务资源定义放 `config/*.yaml`。
2. **配置驱动**：新增资源优先增加配置文件，而不是修改代码。
3. **统一访问**：业务代码通过 Registry 获取资源，不直接依赖名称或路径。
4. **运行时可扩展**：动态策略和用户配置放数据库，由 Web UI 管理。
5. **稳定命名**：Bucket 等基础存储命名保持固定，避免因改名导致数据访问异常。

通过这种分层设计，AI Platform 能够在保持部署灵活性的同时，具备良好的可维护性、可扩展性和长期演进能力。
