# AI Platform 文件生命周期与临时文件管理规范（File Lifecycle Specification）

> Version: v1.0
> Last Update: 2026-07-27

---

# 1. 设计目标

AI Platform 在运行过程中会产生大量不同类型的文件，例如：

- 下载的 PDF
- OCR 图片
- Markdown
- Embedding 数据
- 临时 CSV
- Agent 工作文件
- AI 生成报告
- 日志

如果没有统一管理，长期运行后会导致：

- 磁盘空间不断增长
- 大量无用临时文件
- 数据难以维护
- 无法进行生命周期管理（Lifecycle Management）

因此平台采用统一的文件生命周期（File Lifecycle）管理体系。

---

# 2. 文件分类

平台所有文件统一划分为五类。

```
AI Platform
│
├── Permanent Assets（永久资产）
├── Cache（缓存）
├── Workspace（工作目录）
├── Artifacts（生成产物）
└── Logs（日志）
```

---

# 3. Permanent Assets（永久资产）

## 用途

保存平台长期需要保留的数据。

例如：

- 年报 PDF
- 公司公告
- 研究报告
- Markdown
- 向量数据
- 数据集

这些数据属于知识资产。

---

## 推荐目录

```
MinIO

documents/
knowledge/
datasets/
```

例如

```
documents/
    stock_a/
    stock_h/
    stock_us/

knowledge/
    markdown/
    chunks/

datasets/
    akshare/
    tushare/
```

---

## 生命周期

```
永久保存
```

默认不自动删除。

所有删除必须经过人工确认。

---

# 4. Cache（缓存）

## 用途

缓存用于提升运行效率。

缓存内容包括：

- HTTP 下载缓存
- HTML
- OCR 图片
- PDF 渲染图片
- API Response
- Web Cache

例如

```
cache/

html/
http/
images/
ocr/
pdf/
```

例如：

```
cache/

http/

    cninfo_xxx.html

ocr/

    page001.png

page002.png
```

---

## 生命周期

特点：

- 可以重新生成
- 不属于永久数据
- 删除不会影响系统

例如：

```
重新下载网页

重新 OCR

重新渲染 PDF
```

即可恢复。

---

# 5. Workspace（工作目录）

## 用途

Workspace 是 Agent 工作区域。

Agent 在这里完成：

```
下载

↓

解压

↓

OCR

↓

解析

↓

分析

↓

生成结果
```

例如：

```
workspace/

task_001/

    report.pdf

    image/

    temp/

    output/

task_002/

task_003/
```

每个任务拥有独立 Workspace。

---

## 生命周期

Workspace 仅用于当前任务。

任务结束后：

```
Workspace

↓

删除
```

不会作为永久数据保存。

---

# 6. Artifacts（AI 生成产物）

## 用途

保存 AI 自动生成的结果。

例如：

- Markdown
- PDF
- PPT
- Excel
- Word
- JSON
- 图片
- 图表
- Mermaid
- PlantUML

推荐目录：

```
artifacts/

analysis/

report/

ppt/

excel/

image/

chart/
```

例如：

```
artifacts/

analysis/

    贵州茅台分析报告.pdf

ppt/

    AI投资汇报.pptx

excel/

    财务模型.xlsx
```

---

## 生命周期

默认长期保留。

因为：

用户通常需要：

- 下载
- 查看历史
- 再次打开
- 分享

---

# 7. Logs（日志）

日志用于：

- Debug
- Agent 调试
- Pipeline 调试
- 系统监控

例如：

```
logs/

langgraph/

crawler/

embedding/

docling/

system/

docker/
```

---

## 生命周期

建议：

```
保留 30 天
```

自动轮转。

例如：

```
每天：

压缩

↓

超过30天

↓

自动删除
```

---

# 8. 文件生命周期（Lifecycle）

整个文件生命周期如下：

```
下载

↓

Workspace

↓

处理中

↓

生成结果

↓

Move

↓

MinIO

documents/

knowledge/

artifacts/

↓

Workspace 删除
```

其中：

Workspace 只是加工区。

不是存储区。

---

# 9. Cleanup Service（自动清理服务）

Agent 不负责删除临时文件。

统一交给 Cleanup Service。

例如：

```
每天凌晨

↓

扫描 Workspace

↓

超过24小时

↓

自动删除
```

或者：

```
超过7天

↓

删除
```

可配置。

---

## Cleanup 流程

```
Workspace

↓

检查 Task

↓

Task 已完成

↓

超过保留时间

↓

删除 Workspace
```

---

# 10. Agent Crash 恢复机制

例如：

```
下载 100GB

↓

处理中

↓

Agent Crash
```

Workspace 仍然存在：

```
workspace/

task001/
```

Cleanup Service：

```
扫描

↓

48小时无人使用

↓

删除
```

因此不会留下大量垃圾文件。

# 11. PostgreSQL 元数据管理（推荐）

建议增加 Task 与 Artifact 元数据管理。

例如：

## Tasks

记录：

- Task ID
- 状态
- Workspace 路径
- 创建时间
- 完成时间
- Owner Agent

例如：

| 字段 | 说明 |
|------|------|
| task_id | 任务编号 |
| status | Running / Finished / Failed |
| workspace | 工作目录 |
| created_at | 创建时间 |
| finished_at | 完成时间 |

---

## Artifacts

记录：

- 文件名称
- Bucket
- MinIO Object
- 文件大小
- MIME Type
- Task ID
- Version

例如：

| 字段 | 说明 |
|------|------|
| artifact_id | 文件ID |
| task_id | 所属任务 |
| bucket | MinIO Bucket |
| object_key | Object Key |
| file_size | 文件大小 |
| mime_type | 文件类型 |
| created_at | 创建时间 |

# 12. MinIO Bucket 规划

推荐如下：

| Bucket | 用途 | 生命周期 |
|----------|------|-----------|
| documents | 原始文档 | 永久 |
| knowledge | Markdown、Chunk | 永久 |
| datasets | CSV、Parquet | 永久 |
| artifacts | AI 生成结果 | 长期保留 |
| staging | 上传临时区 | 自动清理 |

# 14. 生命周期总结

| 类型 | 存储位置 | 生命周期 | 自动删除 |
|--------|----------|-----------|-----------|
| 原始 PDF | MinIO documents | 永久 | ❌ |
| Markdown | MinIO knowledge | 永久 | ❌ |
| Chunk | MinIO knowledge | 永久 | ❌ |
| Dataset | MinIO datasets | 永久 | ❌ |
| AI 报告 | MinIO artifacts | 长期 | ❌（可配置） |
| HTTP Cache | cache | 短期 | ✅ |
| OCR 图片 | cache | 短期 | ✅ |
| Workspace | workspace | 当前任务 | ✅ |
| Logs | logs | 30 天 | ✅ |
| staging | MinIO staging | 7 天 | ✅ |

# 15. 设计原则

平台统一遵循以下原则：

1. **Permanent Assets 永不自动删除**。
2. **Workspace 仅作为加工区，不作为存储区**。
3. **Cache 可随时清理，不影响数据完整性**。
4. **Artifacts 为用户可下载成果，默认长期保留**。
5. **Logs 按保留策略自动轮转与清理**。
6. **所有临时文件统一由 Cleanup Service 管理，不由 Agent 自行删除**。
7. **所有文件均应在 PostgreSQL 中维护元数据，实现任务恢复、生命周期管理、审计与版本控制。**

---

# 16. 后续扩展建议（Roadmap）

未来可进一步扩展以下能力：

- **Lifecycle Policy Engine**：按 Bucket、文件类型、任务状态定义生命周期策略。
- **Version Management**：结合 MinIO Versioning，实现文档版本回滚。
- **Storage Tiering**：冷热数据分层存储，降低存储成本。
- **Retention Policy**：支持按项目、用户或任务配置不同保留周期。
- **Garbage Collection（GC）**：自动清理孤立文件（数据库不存在但存储仍存在的对象）。
- **Artifact Registry**：统一管理 AI 生成的 PDF、PPT、图表、代码等产物，并支持版本检索与下载。
