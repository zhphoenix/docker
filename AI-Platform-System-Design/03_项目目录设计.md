# 项目目录设计

## 一、Agent 服务目录结构.

按 Workflow 分类，不按模型分类。新增 Agent 只需增加一个 Graph，不用改其他 Agent。

```text
agent/
├── app/                        # FastAPI 应用入口
│   ├── __init__.py
│   └── main.py                 # FastAPI 实例、生命周期、中间件
│
├── api/                        # API 路由层
│   ├── __init__.py
│   ├── chat.py                 # /v1/chat/completions（OpenAI 兼容）
│   ├── models.py               # /v1/models
│   └── health.py               # /health
│
├── graph/                      # LangGraph 核心
│   ├── __init__.py
│   ├── builder.py              # Graph 构建器（编译 Graph）
│   ├── graph.py                # Graph 定义（节点 + 边 + 条件路由）
│   ├── router.py               # Agent Dispatcher（请求 → Agent 路由）
│   ├── state.py                # AgentState 定义
│   └── checkpoint.py           # PostgreSQL Checkpoint 配置
│
├── agents/                     # Agent 定义
│   ├── __init__.py
│   ├── base_agent.py           # Agent 基类
│   ├── chat_agent.py           # Chat Agent（简单问答 + RAG）
│   ├── research_agent.py       # Research Agent（研究分析）
│   ├── knowledge_agent.py      # Knowledge Agent（知识管理）
│   └── investment_agent.py     # Investment Agent（投研分析）
│
├── nodes/                      # Node 定义（每个 Node 单一职责）
│   ├── __init__.py
│   ├── planner.py              # 生成执行计划
│   ├── retrieve.py             # Embedding + Qdrant 检索
│   ├── rerank.py               # Reranker 重排序
│   ├── reason.py               # LLM 推理
│   ├── reflect.py              # 检查答案质量
│   ├── writer.py               # 输出最终结果
│   └── finish.py               # 结束处理
│
├── tools/                      # Tool 定义（只访问基础设施）
│   ├── __init__.py
│   ├── llm.py                  # llama.cpp API 调用
│   ├── qdrant.py               # Qdrant 向量检索
│   ├── postgres.py             # PostgreSQL 查询
│   ├── embedding.py            # Embedding 服务调用
│   ├── reranker.py             # Reranker 服务调用
│   ├── docling.py              # Docling 文档解析
│   ├── obsidian.py             # Obsidian Vault 读写
│   ├── minio.py                # MinIO 文件操作
│   ├── filesystem.py           # 本地文件系统
│   └── search.py               # Web 搜索（预留）
│
├── prompts/                    # Prompt 模板（独立管理）
│   ├── planner.md              # 通用 Planner
│   ├── reason.md               # 通用 Reason
│   ├── reflect.md              # 通用 Reflect
│   ├── writer.md               # 通用 Writer
│   ├── chat/system.md          # Chat Agent 专用
│   ├── research/system.md      # Research Agent 专用
│   ├── investment/system.md    # Investment Agent 专用
│   └── loader.py               # Prompt Loader（统一加载）
│
├── schemas/                    # Pydantic 数据模型
│   ├── __init__.py
│   ├── chat.py                 # 请求/响应模型
│   └── state.py                # State Schema
│
├── memory/                     # Memory 管理
│   ├── __init__.py
│   └── checkpoint.py           # Checkpoint 相关
│
├── config/                     # 配置管理
│   ├── __init__.py
│   └── settings.py             # Pydantic Settings（从 .env 加载）
│
├── tests/                      # 测试
│   ├── __init__.py
│   ├── unit/                   # 单元测试
│   ├── integration/            # 集成测试
│   └── api/                    # API 测试
```

## 三、MinIO Bucket 目录规范

> **完整规范见 [24_数据底座规范](24_数据底座规范.md) 第二章。**

### 3.1 Bucket 总览

| Bucket | 用途 | 生命周期 |
|--------|------|----------|
| `documents` | 原始文件和已解析文档（PDF + MD + metadata.json） | 永久 |
| `knowledge` | Agent 提取的结构化知识（财务报表/摘要/时间线） | 永久 |
| `datasets` | 外部数据集（tushare/akshare/macro/industry，CSV/Parquet） | 永久 |
| `artifacts` | 生成产物（研报/摘要/PPT/Obsidian 同步） | 永久 |
| `staging` | 临时文件（下载/OCR/chunk/重试队列） | 完成后自动清空 |

### 3.2 documents/ 目录结构

按 `市场 → 股票代码 → 文档类型 → 年份` 组织：

```text
documents/
├── cn/                          # 市场
│   └── 600519/                  # 股票代码
│       ├── annual_report/       # 文档类型
│       │   └── 2025/            # 年份
│       │       ├── report.pdf   # 原始文件
│       │       ├── report.md    # Docling 解析结果
│       │       ├── metadata.json
│       │       ├── chunks.json  # 切块结果
│       │       ├── tables/      # 独立表格（table001.md, table002.csv）
│       │       └── figures/     # 独立图片（figure001.png）
│       ├── announcement/        # 公告
│       ├── news/                # 新闻
│       ├── research/            # 研报
│       └── prospectus/          # 招股书
├── hk/
│   └── 00700/
└── us/
    └── aapl/
```

### 3.5 文件命名规范

**内部存储**（目录已含上下文，文件名保持简洁）：
- `report.pdf` / `report.md` / `metadata.json` / `chunks.json`
- `table001.md` / `table002.csv` / `figure001.png`

**外部交换**（跨系统传输时使用完整命名模板）：
```text
<Domain>_<Identifier>_<Version>_<Date>.<ext>
```
示例：`finance_600519_SH_2025_AR.pdf`

> 完整命名规则见 [24_数据底座规范](24_数据底座规范.md) 第 2.3 节。

## 四、Obsidian Vault 目录结构

```text
/mnt/e/Knowledge/Vault/
├── 00_Inbox/                   # 待整理内容（Agent 临时输出）
├── 01_Daily/                   # 每日笔记
├── 02_Projects/                # 项目文件
├── 03_Investment/              # 投研核心
│   ├── Companies/              # 公司研究（Agent 写入 + 人编辑）
│   ├── Industries/             # 行业分析
│   ├── Reports/                # 研究报告（Research Agent 输出）
│   └── Research/               # 研究笔记（投资人认知，Agent 可读）
├── 04_AI/                      # AI 相关
├── 05_Programming/             # 编程笔记
├── 06_Books/                   # 读书笔记
├── 07_Notes/                   # 通用笔记
├── Attachments/                # 附件
└── Templates/                  # 模板
```

### Agent 写入规范

| Agent | 写入目录 | 命名规范 |
|-------|---------|----------|
| Research Agent | `03_Investment/Reports/{symbol}/` | `YYYY-MM-DD-{topic}.md` |
| Investment Agent | `03_Investment/Companies/{symbol}/` | `{analysis_type}.md` |
| Knowledge Agent | 全 Vault（维护标签和 frontmatter） | - |

### Agent 读取源

| Agent | 读取目录 | 用途 |
|-------|---------|------|
| Research Agent | `03_Investment/Research/` | 投资人历史研究笔记作为上下文 |
| Investment Agent | `03_Investment/Companies/{symbol}/` | 已有公司研究结论 |
| Knowledge Agent | 全 Vault | 标签索引、重复检测 |

## 五、设计原则

| 原则 | 说明 |
|------|------|
| 按 Workflow 分类 | 不按模型分类，新增 Agent 只增加 Graph |
| Node 单一职责 | 每个 Node 只负责一件事 |
| Tool 只访问基础设施 | 不包含业务逻辑 |
| Prompt 独立管理 | 独立文件，统一加载 |
| 永远不用中文命名 | 文件名、目录名全部英文 |
| 目录已含上下文，文件名不重复 | `600519/annual_report/2025/report.pdf` 而非 `600519_2025_年报.pdf` |
| 公司用代码不用名称 | 代码不变，名称会变（如 600519 不变，贵州茅台可能改名） |
