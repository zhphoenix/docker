# 一、设计目标

Data Access Layer（DAL）是 AI Platform 的统一数据访问入口。

所有 Agent、Workflow、Research Pipeline、RAG、Web UI 不直接调用 AKShare、TuShare、Yahoo Finance 等数据源，而是统一通过 Data Access Layer。

整体架构如下：

```
                    Agent
                      │
                      ▼
          Source Selection Agent
                      │
                      ▼
        ┌─────────────────────────┐
        │   Data Access Layer      │
        └─────────────────────────┘
                      │
      ┌───────────────┼────────────────┐
      │               │                │
      ▼               ▼                ▼
 Provider         Cache Layer     Metadata
 Manager                          Registry
      │
      ▼
┌─────┼───────────────────────────────────────────┐
│ AKShare │ TuShare │ Crawl4AI │ EDGAR │ HKEX ... │
└─────────────────────────────────────────────────┘
                      │
                      ▼
          MinIO / PostgreSQL / Qdrant
```

Data Access Layer 的目标：

- 屏蔽底层数据源差异
- 自动选择最佳 Provider
- 自动切换故障数据源
- 统一数据格式
- 数据缓存
- 数据审计
- 长期可扩展

# 二、设计原则

## 2.1 Agent 永远不知道数据源

错误：

```
Agent
   ↓
AKShare
```

正确：

```
Agent
   ↓
Data Access Layer
   ↓
AKShare
```

Agent 不应该知道：

- API 地址
- Token
- SDK
- Provider 名称

Agent 只描述：

> 我要什么数据。

例如：

```
获取贵州茅台近五年ROE
```

而不是：

```
调用 AKShare stock_financial...
```

---

## 2.2 Provider 可插拔

新增数据源时：

```
Provider/
    akshare.py
    tushare.py
    yahoo.py
    sec.py
```

无需修改 Agent。

新增：

```
provider/wind.py
```

即可。

---

## 2.3 数据格式统一

所有 Provider 返回统一对象。

例如：

```
DataResult

{
    provider,
    timestamp,
    data,
    metadata
}
```

禁止：

AKShare 返回 DataFrame

TuShare 返回 dict

Yahoo 返回 list

所有 Provider 必须统一。

建议：

```
Pandas DataFrame
```

或

```
Arrow Table
```

内部统一。

跨服务：

统一：

```
JSON
```

# 四、Source Router

负责：

根据任务选择最佳 Provider。

例如：

```
600519

↓

中国A股

↓

TuShare

↓

失败

↓

AKShare
```

例如：

```
AAPL

↓

Yahoo Finance
```

例如：

```
BTC

↓

CCXT
```

---

Router 不允许：

```
if code.startswith("6")
```

散落在项目各处。

必须集中管理。

---

# 五、Provider Manager

负责：

管理所有 Provider。

目录建议：

```
providers/

    base.py

    akshare.py

    tushare.py

    eastmoney.py

    sina.py

    yahoo.py

    sec.py

    hkex.py

    crawl4ai.py

    custom.py
```

所有 Provider 必须实现统一接口。

例如：

```
BaseProvider

search()

download()

query()

health_check()
```

# 十九、最佳实践

✅ 所有 Agent 必须通过 Data Access Layer 获取数据。

✅ 所有 Provider 必须实现统一接口。

✅ 所有数据返回统一 DataResult。

✅ Source Router 负责 Provider 自动选择。

✅ Failover 自动切换异常 Provider。

✅ Cache 减少重复请求。

✅ Metadata Registry 管理 Provider 能力。

✅ Logger 全程记录调用过程。

✅ Data Access Layer 不负责业务逻辑，仅负责数据访问。

# 二十、长期演进路线（Roadmap）

## Phase 1：统一访问

- 建立 BaseProvider 接口
- 接入 AKShare、TuShare、Yahoo Finance
- 实现统一 DataResult

## Phase 2：智能路由

- Source Router
- Provider 优先级
- 自动故障切换
- 自动健康检测

## Phase 3：数据治理

- Metadata Registry
- 数据血缘（Data Lineage）
- 数据质量评分
- 数据可信度评估

## Phase 4：智能数据平台

- Source Selection Agent
- 多 Provider 协同
- 自动成本优化
- 自动缓存策略
- 多 Agent 数据协同
- 企业级 Data Fabric

---

 Data Access Layer 是 AI Platform 的统一数据入口，负责屏蔽数据源差异、统一访问接口、保障数据质量与可靠性。通过 Provider 可插拔架构、智能路由、缓存、故障切换和元数据管理，为多 Agent 投资研究平台提供稳定、可扩展、可审计的数据底座。这一层不仅支撑当前的股票、公告、研报与文档知识库，也为未来接入商业数据源、更多市场以及企业级 Data Fabric 奠定基础。
