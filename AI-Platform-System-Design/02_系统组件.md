## 二、各组件详细说明

### 2.1 Open WebUI（Presentation Layer）

- **定位**：用户交互界面，通过 HTTP/OpenAI Compatible API 与后端通信
- **镜像**：`ghcr.io/open-webui/open-webui:v0.10.2-cuda`
- **端口**：3000 → 容器内 8080
- **对接方式**：配置 `OPENAI_API_BASE_URL` 指向 FastAPI
- **数据卷**：`open-webui:/app/backend/data`
- **关键环境变量**：
  ```yaml
  OPENAI_API_BASE_URL: http://host.docker.internal:8100/v1
  OPENAI_API_KEY: dummy
  ```

### 2.2 FastAPI（API Gateway Layer）

- **定位**：提供 OpenAI Compatible API，接收 Open WebUI 请求，调用 Agent Dispatcher
- **端口**：8100
- **职责**：
  - 实现 `/v1/chat/completions`、`/v1/models` 等接口
  - 路由请求到对应 Agent
  - 不包含业务逻辑
- **技术栈**：FastAPI + Uvicorn + SSE 流式响应

### 2.3 LangGraph（Agent Orchestration Layer）

- **定位**：Agent 编排框架（Workflow Engine），不是 AI，不负责回答
- **角色**：导演（Director），不是演员
- **核心能力**：
  - 状态管理（State）
  - 多 Agent 协作
  - 人工介入（Human-in-the-loop）
  - 任务恢复（Checkpoint）
  - 反思与经验保存（Reflection）
- **部署方式**：内嵌 FastAPI 进程，不作为独立服务
- **Checkpoint**：使用 PostgreSQL（AsyncPostgresSaver），Redis 非必需

### 2.4 llama.cpp LLM（LLM Layer）

- **定位**：本地大语言模型推理引擎
- **端口**：8080
- **镜像**：`ghcr.io/ggml-org/llama.cpp:server-cuda13`
- **模型**：Qwen3 系列（GGUF 格式）
- **API**：OpenAI Compatible `/v1/chat/completions`
- **GPU**：NVIDIA CUDA 加速

### 2.5 Embedding 服务（RAG Layer）

- **定位**：文本向量化，将 Chunk 转换为 Embedding 向量
- **端口**：8001 → 容器内 8080
- **模型**：Qwen3-Embedding-4B（f16 未量化精度）
- **模型文件**：`/mnt/g/models/unsloth/Qwen3-Embedding-4B-f16.gguf`
- **API**：`POST /v1/embeddings`（OpenAI 兼容）
- **说明**：向量化对精度敏感，使用 f16 未量化版本

### 2.6 Reranker 服务（RAG Layer）

- **定位**：对检索结果进行重排序，提升 RAG 质量
- **端口**：8002 → 容器内 8080
- **模型**：Qwen3-Reranker-0.6B（Q8_0 量化）
- **模型文件**：`/mnt/g/models/unsloth/Qwen3-Reranker-0.6B-Q8_0.gguf`
- **API**：`POST /v1/rerank`
- **关键参数**：`--reranking --embedding --pooling rank --ctx-size 4096`

### 2.7 Docling（Document Parsing Layer）

- **定位**：文档解析引擎，PDF → DoclingDocument → Chunk → Markdown
- **端口**：5001
- **镜像**：`quay.io/docling-project/docling-serve-cu128:latest`
- **核心流程**：
  ```
  PDF → Layout Model → TableFormer → Reading Order → DoclingDocument
                                                        │
                                              ┌─────────┴─────────┐
                                              ▼                   ▼
                                     HierarchicalChunker     导出 Markdown
                                              │
                                              ▼
                                          多个 Chunk
                                              │
                                              ▼
                                         Embedding → Qdrant
  ```
- **内部模型**：Layout Detection、Table Recognition、OCR、Reading Order、Figure Detection、Formula Detection、Picture Classification
- **GPU**：CUDA 12.8 加速

### 2.8 PostgreSQL（Structured Data Layer）

- **定位**：业务真相源（Source of Truth）
- **端口**：5432
- **镜像**：`pgvector/pgvector:pg17`（内置 pgvector 扩展）
- **存储内容**：
  - 文档处理状态（documents 表）
  - 公司信息（companies 表）
  - 研究任务（research_tasks 表）
  - LangGraph Checkpoint（langgraph 数据库）
  - 财务数据、Agent 任务状态、思考轨迹
- **关键配置**：
  - `shared_buffers=256MB`
  - `effective_cache_size=512MB`
  - `max_connections=50`
- **注意**：WSL2 NTFS 挂载盘不支持 chmod，需用 named volume

### 2.9 Qdrant（Vector Layer）

- **定位**：语义检索索引，保存"理解后的知识"
- **端口**：6333（HTTP）/ 6334（gRPC）
- **镜像**：`qdrant/qdrant`
- **存储内容**：文档 Chunk 经 Embedding 后的向量 + 元数据
- **优化配置**：
  - `ON_DISK_PAYLOAD=true`（磁盘存储 payload）
  - `HNSW_INDEX__ON_DISK=true`（磁盘存储 HNSW 索引）
  - `MEMMAP_THRESHOLD_KB=20000`
- **注意**：表格数据不进入 Qdrant，向量数据库不擅长精确数字查询

### 2.10 MinIO（Storage Layer）

- **定位**：文件真相源（Source of Truth），整个 AI 数据底座的中心
- **端口**：9000（API）/ 9001（Console）
- **镜像**：`quay.io/minio/minio:RELEASE.2025-07-23T15-54-02Z`
- **Bucket 规划**：

| Bucket | 用途 | 内容 |
|--------|------|------|
| `documents` | 原始文档 | PDF、Word、HTML、图片、公告、招股书 |
| `knowledge` | AI 知识资产 | Chunk JSON、OCR 结果、Docling 输出、Embedding 缓存 |
| `datasets` | 数据集 | CSV、Parquet、财务数据、行业数据、宏观数据 |
| `artifacts` | Agent 输出 | 研究报告、Markdown、PDF、PPT |
| `staging` | 临时处理中 | 自动清理 |

- **目录规范**：`{bucket}/{market}/{symbol}/{document_type}/{year}/{file}`
  - 示例：`documents/cn/600519/annual_report/2025/report.pdf`
- **命名规范**：永远不用中文，用简洁英文名（目录已说明上下文，文件名不重复）

### 2.11 Obsidian（Knowledge Layer — 知识操作系统）

- **定位**：投资人的 Personal Knowledge Base，不是数据库，是知识沉淀与编辑工具
- **Vault 路径**：`/mnt/e/Knowledge/Vault/`
- **与 AI 连接方式**：通过 MCP 协议（Local REST API 插件 :27124）暴露给 LangGraph Agent
- **核心角色**：AI 写入 Vault，Obsidian 负责展示和编辑；Agent 也能读取投资人笔记作为上下文

```
            投资者
               │
          ┌────┴────┐
          ▼         ▼
     编辑/标注    阅读/浏览
          │         ▲
          ▼         │
     ┌──────────────────┐
     │  Obsidian Vault   │ ← 知识操作系统
     │  (Markdown 源)    │
     └────────┬─────────┘
              │ MCP 协议
    ┌─────────┼─────────┐
    ▼         ▼         ▼
 Research  Investment  Knowledge
  Agent     Agent      Agent
```

- **多 Agent 共享**：Vault 是 Agent 间异步协作的媒介
  - Research Agent 写入研究报告 → `03_Investment/Reports/`
  - Investment Agent 读取引用 → `03_Investment/Companies/`
  - Knowledge Agent 维护索引 → 全 Vault 标签和 frontmatter
- **前置条件**：
  - Windows 侧安装 Obsidian 并打开 `E:\Knowledge\Vault`
  - 安装 Local REST API 插件（端口 27124）
  - MCP 服务依赖 Obsidian 桌面端运行

## 三、四大存储职责边界

| 存储 | 职责 | 保存什么 | 不保存什么 |
|------|------|---------|----------|
| **PostgreSQL** | 业务真相源 | 事实数据：股票行情、公司信息、Agent 任务、文档处理状态 | 向量、文件 |
| **Qdrant** | 语义检索索引 | 理解后的知识：Chunk Embedding 向量 + 元数据 | 原始文件、精确数值 |
| **MinIO** | 文件真相源 | 原始文件：PDF、Markdown、图片、数据集 | 向量、关系型数据 |
| **Obsidian** | 投资思想库 | 投资思想：研究结论、行业认知、投资逻辑、关联关系 | 全部年报原文、向量 |

## 四、Memory 三层分类

| 记忆类型 | 存储位置 | 说明 |
|---------|---------|------|
| 工作记忆 | PostgreSQL / Redis（未来） | 当前任务的短期上下文 |
| 情景记忆（Episodic） | PostgreSQL | Agent 的思考过程、任务执行记录 |
| 知识记忆 | Qdrant + Obsidian | 语义检索知识 + 长期研究沉淀 + Agent 共享知识空间 |
