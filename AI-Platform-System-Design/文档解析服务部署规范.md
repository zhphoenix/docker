# AI Platform 文档解析服务部署规范
**Document Parsing Service Specification**

Version：v1.0  
Last Update：2026-07-29

---

# 一、目标

建立 AI Platform 的统一 Document Parsing Service，负责所有文档解析工作，而不是让各个 Agent 直接调用某一种 OCR 模型。

统一入口具有以下优势：

- 支持多种 OCR 引擎
- 自动选择最佳解析器
- 易于升级
- 易于监控
- 与业务解耦

整个 AI Platform：

```

PDF / Image

↓

Document Parsing Service

↓

Markdown / JSON / HTML / LaTeX

↓

Chunk Service

↓

Embedding

↓

Vector Database

↓

LangGraph Agent

↓

Web UI

```

# 四、推荐 Docker 服务

```
services:

  paddleocr:
    image: ccr-2vdh3abv-pub.cnc.bj.baidubce.com/paddlepaddle/paddleocr-genai-vllm-server:latest-nvidia-gpu

    container_name: paddleocr-vl

    restart: unless-stopped

    network_mode: host

    shm_size: "8g"

    environment:
      NVIDIA_VISIBLE_DEVICES: all

    deploy:
      resources:
        reservations:
          devices:
            - driver: nvidia
              count: 1
              capabilities:
                - gpu

    volumes:
      - ./services/paddleocr/vllm_config.yaml:/tmp/vllm_config.yaml

    command: >
      paddleocr genai_server
      --model_name PaddleOCR-VL-1.6-0.9B
      --backend vllm
      --host 0.0.0.0
      --port 8118
      --backend_config /tmp/vllm_config.yaml
```

# 五、推荐 vLLM 配置

针对 RTX 5060 Ti 16GB：

```
gpu_memory_utilization: 0.85

max_num_seqs: 4

tensor_parallel_size: 1

dtype: bfloat16

trust_remote_code: true

enforce_eager: false
```

说明：

| 参数 | 推荐值 | 说明 |
|-------|---------|------|
| gpu_memory_utilization | 0.85 | 留部分显存给其它服务 |
| max_num_seqs | 4 | 控制并发 |
| tensor_parallel_size | 1 | 单 GPU |
| dtype | bfloat16 | 官方推荐 |
| trust_remote_code | true | Paddle 官方模型需要 |
| enforce_eager | false | 保持最佳性能 |

# 八、OCR 输出格式

推荐全部保存。

## Markdown

用于：

- RAG
- Chunk
- LLM

例如：

```
# 公司简介

......

## 财务数据

......
```

---

## JSON

保存结构信息。

例如：

```json
{
  "page": 1,
  "blocks": [
    {
      "type": "title",
      "text": "...",
      "bbox": [...]
    },
    {
      "type": "table",
      "html": "<table>...</table>"
    }
  ]
}
```

推荐：

保存 PostgreSQL JSONB。

---

## HTML

保留表格：

```
<table>
...
</table>
```

适合：

- Web UI
- 导出 Word
- Excel

---

## LaTeX

保存数学公式：

```
\sum_i x_i
```

方便：

- 学术论文
- 金融公式
- 科研文档

# 十、统一 Document Parsing Service

推荐不要让任何 Agent 直接调用 PaddleOCR。

而是：

```

Document Parsing Service

│

├── Docling

├── PaddleOCR-VL

├── MinerU（未来）

├── PP-OCRv6

├── DeepSeek-OCR

└── HunyuanOCR（未来）

```

统一接口：

```
POST /parse
```

参数：

```
{
    "file":"annual_report.pdf",
    "mode":"auto"
}
```

自动判断：

- PDF
- 扫描件
- 图片
- Word
- PPT
- Excel

自动选择最佳解析器。

# 十六、总结

建议将 OCR 从单一模型升级为 AI Platform 的 **Document Parsing Service**。

核心原则：

- **统一入口（Single Entry）**
- **多模型可插拔（Pluggable Providers）**
- **统一输出格式（Markdown + JSON + HTML + LaTeX）**
- **统一存储（PostgreSQL + MinIO + Qdrant）**
- **与 Agent 解耦（Loose Coupling）**
- **便于未来升级（Future-proof）**

这种架构能够支持 PaddleOCR、MinerU、DeepSeek-OCR 等模型的持续演进，同时保持上层 LangGraph、RAG 和 Web UI 的稳定性，是适合企业级 AI Platform 的长期方案。
