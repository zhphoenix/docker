# 开发规范

## 一、分层架构

```text
API Layer（api/）
    │
    ▼
Agent Layer（agents/）
    │
    ▼
Graph Layer（graph/）
    │
    ▼
Node Layer（nodes/）
    │
    ▼
Tool Layer（tools/）
    │
    ▼
Infrastructure（PostgreSQL / Qdrant / MinIO / Docling / LLM）
```

---

## 二、核心规范

### 2.1 Layer 分离

| 规则 | 说明 |
|------|------|
| API 不含业务逻辑 | 只负责 HTTP 协议、请求校验、响应格式化 |
| Graph 不访问数据库 | 只编排 Workflow，通过 Node 调用 Tool |
| Node 不直接访问基础设施 | 通过 Tool 访问外部服务 |
| Tool 不含业务逻辑 | 只封装外部服务调用 |

### 2.2 Node 规范

```python
# ✅ 正确：Node 通过 Tool 访问外部服务
async def retrieve(state: AgentState) -> dict:
    vectors = await embedding_tool.embed([state["question"]])
    results = await qdrant_tool.search(collection="documents_cn", vector=vectors[0])
    return {"documents": results}

# ❌ 错误：Node 直接访问数据库
async def retrieve(state: AgentState) -> dict:
    conn = await asyncpg.connect(...)  # 不应该在 Node 中
```

### 2.3 Tool 规范

```python
# ✅ 正确：Tool 只访问基础设施
class QdrantTool:
    async def search(self, collection: str, vector: list[float]) -> list[dict]:
        ...

# ❌ 错误：Tool 包含业务逻辑
class QdrantTool:
    async def search_and_analyze(self, ...):  # 不应该在 Tool 中分析
        ...
```

### 2.4 Prompt 规范

- 所有 Prompt 独立保存在 `prompts/` 目录
- 使用 `.md` 文件格式
- 通过 Prompt Loader 统一加载
- 不硬编码在 Node 中

## 三、命名规范

| 类型 | 规范 | 示例 |
|------|------|------|
| 文件名 | snake_case | `retrieve.py` |
| 类名 | PascalCase | `QdrantTool` |
| 函数名 | snake_case | `def search()` |
| 常量 | UPPER_SNAKE_CASE | `MAX_RETRY_COUNT` |
| 目录 | snake_case | `agents/` |
| 配置键 | UPPER_SNAKE_CASE | `OPENAI_BASE_URL` |

---

## 四、代码组织

- 每个文件只关注单一职责
- 相关功能放在同一目录
- 公共工具函数放在 `utils/`
- 类型定义放在 `schemas/`

---

## 五、依赖方向

```text
api → agents → graph → nodes → tools → config
                                    ↓
                              infrastructure
```

**禁止反向依赖**：Tool 不能 import Node，Node 不能 import API。

## 六、业务文件命名规范

建立一个长期维护的投资研究平台，采用统一的业务命名规范。

### 6.1 命名模板

```text
<Domain>_<Identifier>_<Version>_<Date>.<ext>
```

### 6.2 各字段定义

| 字段 | 说明 | 示例 |
|------|------|------|
| `Domain` | 业务领域 | `finance`（金融）、`law`（法规）、`book`（书籍）、`paper`（论文）、`note`（笔记） |
| `Identifier` | 唯一标识符 | 股票代码（`600519_SH`）、法规机构（`CSRC`）、ISBN、DOI |
| `Version` | 版本/类型 | `AR`（年报）、`Q2`（二季报）、日期（`20250601`） |
| `Date` | 日期 | `YYYYMMDD` 或 `YYYY` |
| `ext` | 文件扩展名 | `.pdf`、`.md`、`.xlsx` |

### 6.3 示例

| 文件 | 说明 |
|------|------|
| `finance_600519_SH_2025_AR.pdf` | 贵州茅台 2025 年报 |
| `finance_600519_SH_2025_Q2.pdf` | 贵州茅台 2025 二季报 |
| `finance_000001_SZ_2025_AR.pdf` | 平安银行 2025 年报 |
| `law_CSRC_20250601.pdf` | 证监会 2025-06-01 法规 |
| `book_ISBN9787111123456.pdf` | ISBN 书籍 |
| `paper_DOI10.1038xxxx.pdf` | DOI 论文 |
| `note_OBS_20260717.md` | Obsidian 笔记 |

### 6.4 原则

| 原则 | 说明 |
|------|------|
| 永远不用中文 | 文件名、目录名全部英文 |
| 目录已含上下文，文件名不重复 | `finance/600519/2025/report.pdf` 而非 `finance_600519_SH_2025_AR.pdf` |
| 公司用代码不用名称 | 代码不变，名称会变（如 600519 不变，贵州茅台可能改名） |
| 与 MinIO 目录规范互补 | MinIO 内部用目录结构（`documents/cn/600519/...`），外部导出/交换时用此命名规范 |
