# Watchlist 智能监控 页面重构设计方案

# 1. 设计目标

当前页面主要围绕：

- 添加股票
- 删除股票
- 开启/关闭监控

组织页面。

实际上，这只是配置工作，占整个功能的 5%。

真正的价值应该是：

> AI 每天帮我监控什么？
> 今天有哪些股票需要关注？
> 哪些事件影响了我的持仓？

因此建议整个页面围绕：

**Monitoring（监控）**

而不是：

**Watchlist（列表）**

---

# 2. 页面定位

建议名称：

> Watchlist Intelligence Center

副标题：

> 自选股监控 · 新闻 · 公告 · 财报 · 行业 · 风险 · AI 分析

进入页面第一眼应该回答：

今天发生了什么？

而不是：

添加股票。

---

# 3. 页面整体结构

建议整个页面拆成六个区域。

```
Watchlist Intelligence Center
────────────────────────────

① Today Overview（今天发生了什么）

② Alerts（需要处理）

③ Watchlist（股票）

④ Monitoring Configuration（监控配置）

⑤ Reports（日报）

⑥ History（历史）
```

整个页面围绕监控生命周期展开。

# 14. 与整体平台的关系

Watchlist 不应只是保存股票列表，而应作为 **Research Agent 的主动触发器**。

完整工作流建议如下：

```
用户添加股票
        │
        ▼
Watchlist Service
        │
        ▼
Scheduler（定时任务）
        │
        ▼
News Pipeline
        │
        ▼
Knowledge Pipeline
        │
        ▼
Entity / Relation / Fact 更新
        │
        ▼
Research Agent 分析
        │
        ▼
Risk Detection
        │
        ▼
Alert Center
        │
        ▼
Daily Report
        │
        ▼
Dashboard 展示
```

# 16. 最终定位

Watchlist 模块不应定位为**股票收藏夹（Watchlist Manager）**，而应定位为平台的**智能监控与事件中心（Intelligence Monitoring Center）**。

它负责连接新闻采集、知识图谱、Research Agent 和告警系统，持续跟踪用户关注的标的，并将海量信息转化为可执行的投资洞察。
