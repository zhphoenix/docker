# LangGraph Docker 开发模式重构计划

## 背景

当前 `langgraph/Dockerfile` 第 10 行 `COPY agent/ .` 将业务代码固化到镜像中，导致每次修改 Python 代码都必须 `docker compose up -d --build`。根据 Docker 开发规范核心原则："Docker 管环境，不管业务代码；Image 管依赖，Volume 管变化"。

## 现状分析

| 文件 | 当前状态 |
|------|----------|
| `langgraph/Dockerfile` | COPY agent/ . 将代码打包进镜像 |
| `langgraph/compose.yml` | build + 无代码 volume 挂载 |
| `langgraph/agent/main.py` | 已支持 `RELOAD` 环境变量控制 uvicorn --reload |

关键发现：`main.py` 已预留热更新开关（第 8 行 `RELOAD` env），只需在 compose 中启用。

---

## Phase 1: 创建开发专用 Dockerfile

**文件**: `langgraph/Dockerfile.dev`（新建）

```dockerfile
FROM python:3.11-slim

WORKDIR /app

# 仅安装 Python 依赖（不 COPY 业务代码）
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

EXPOSE 8100

# 开发模式：代码通过 Volume 挂载到 /app
CMD ["python", "main.py"]
```

与原 Dockerfile 唯一区别：移除 `COPY agent/ .` 这一行。

---

## Phase 2: 重构 compose.yml（开发模式）

**文件**: `langgraph/compose.yml`

变更点：
1. `build.dockerfile` 改为 `Dockerfile.dev`
2. `volumes` 新增代码挂载 `./agent:/app`
3. `environment` 新增 `RELOAD: "true"`

```yaml
services:
  langgraph:
    build:
      context: .
      dockerfile: Dockerfile.dev    # 改：使用开发 Dockerfile
    container_name: langgraph
    ports:
      - "8100:8100"
    env_file:
      - ../.env
    environment:
      RELOAD: "true"                # 新增：启用 uvicorn --reload
      # ... 其余环境变量保持不变 ...
    volumes:
      - ./agent:/app                # 新增：代码目录挂载
      - /mnt/e/ai-platform/data/obsidian_vault:/vault
      - /mnt/e/ai-platform/data/reports:/data/analysis_reports:ro
    # ... networks, healthcheck, deploy, logging 保持不变 ...
```

注意事项：
- `./agent:/app` 挂载后，容器内 /app 即为宿主机 `langgraph/agent/` 目录
- pip 依赖安装在系统 site-packages（非 /app），不受 volume 覆盖影响
- 数据卷 `/vault`、`/data/analysis_reports:ro` 保持原样

---

## Phase 3: 创建生产环境 compose（镜像固化）

**文件**: `langgraph/compose.prod.yml`（新建）

```yaml
services:
  langgraph:
    build:
      context: .
      dockerfile: Dockerfile        # 使用原 Dockerfile（含 COPY agent/）
    container_name: langgraph
    ports:
      - "8100:8100"
    env_file:
      - ../.env
    environment:
      RELOAD: "false"               # 生产禁用 reload
      # ... 与 compose.yml 相同的容器名直连环境变量 ...
    volumes:
      # 生产模式：不挂载代码，仅挂载数据卷
      - /mnt/e/ai-platform/data/obsidian_vault:/vault
      - /mnt/e/ai-platform/data/reports:/data/analysis_reports:ro
    networks:
      - ai-platform
    # ... healthcheck, deploy, logging 同 compose.yml ...

networks:
  ai-platform:
    external: true
```

---

## Phase 4: 优化 uvicorn reload 配置

**文件**: `langgraph/agent/main.py`

增加 `reload_dirs` 限定监听范围，避免监听 `tests/`、`__pycache__` 等无关目录：

```python
if __name__ == "__main__":
    reload = os.getenv("RELOAD", "false").lower() == "true"
    uvicorn.run(
        "app.main:app",
        host="0.0.0.0",
        port=8100,
        reload=reload,
        reload_dirs=["."] if reload else None,
        reload_excludes=["tests/*", "__pycache__/*", "*.pyc"] if reload else None,
        log_level="info",
    )
```

`langgraph/Dockerfile` 保持现状（含 `COPY agent/ .`），作为生产构建使用。无需修改。

## 回滚方案

如热更新模式出现问题，一条命令回滚到旧模式：
```bash
# 停止开发模式
docker compose down
# 使用生产 compose 启动（等同于旧行为）
docker compose -f compose.prod.yml up -d --build
```

原 Dockerfile 未被修改，随时可切回。

---

## 变更影响矩阵

| 变更类型 | 是否需要 rebuild | 说明 |
|----------|:---:|------|
| Agent/Skill/Tool/Node 代码 | 否 | Volume 挂载 + reload 自动生效 |
| Prompt/YAML 配置 | 否 | 同上 |
| requirements.txt 依赖 | 是 | pip 依赖在镜像内 |
| 系统包（apt） | 是 | 需修改 Dockerfile.dev |
| 基础镜像版本 | 是 | 需修改 Dockerfile.dev |
| 环境变量 | 否 | docker compose up -d（无需 --build） |
